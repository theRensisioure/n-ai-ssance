# Socratic series · Map, not chat dump

*Ground story (sterile): Alex, River, example-app — see use-cases/01.*

## Spine (mirror)

The load-bearing move is **handoff without transcript** — not “summarize better.”

## Sequenced prompts (one at a time in chat)

**P1.** When River asks where the login bug left off, what single sentence would you want already written—before any agent opens the jsonl?

**P2.** If that sentence is missing, is the failure *memory*, *tooling*, or *permission to stop and map*? Pick one primary; name the secondary.

**P3.** What is the smallest artifact that would make pasting the transcript feel *obviously worse*?

**P4.** Which field on the map do you actually use—relay, spine, paths, or identity—and which do you keep “for completeness” only?

**P5.** When have you used a map to *avoid* work that felt urgent but was out of spine?

## Seeds if stuck (≤5)

1. Write River’s handoff line in 20 words.  
2. Delete one map field and notice what breaks.  
3. Name a time a dump helped and a time it harmed.  
4. Decide: map is for humans, agents, or both first.  
5. Park “perfect map schema” until one real handoff succeeds.

## Done-when (for this series)

You can state the benefit of map-not-chat in one concrete story without defending a product feature list.
