# Use case · Reconstruct from disk

## Situation (synthetic)

Alex closed the coach chat overnight. Morning: empty new session.  
Fear: “I lost the day.”  
On disk: a day board for **example-app** work (queues, closed, parked) and a session pin file.

## Approach

**Reconstruct** = re-read disk every time:

- Active queue / slot (work names first)  
- Carry and parked (named, not guilt)  
- Closed (credit)  
- Optional save as a **new stamped** file — never overwrite  

No streaming “continue the old mind.” Fresh instance, **re-membered**.

## Benefit

- Continuity without pretending chat is durable state  
- Interrupt recovery is a **procedure**, not a personality trait  
- Board indices stay secondary to human task names  

## If skipped

Alex restarts from vibe, reopens five half-features, and the day board becomes fiction.
